# دوراتو | Doratou Backend

**بک‌اند پلتفرم مدیریت دورهمی، سفر و برنامه‌های دوستانه**

دوراتو برای هر برنامهٔ دوستانه یک «اکیپ» می‌سازد؛ فضایی مشترک برای هماهنگی، تقسیم هزینه‌ها، تصمیم‌گیری و نگهداری خاطرات. هدف محصول این است که اعضا از زمان دعوت تا تسویه و آرشیو برنامه، ابزارهای موردنیازشان را در یک جا داشته باشند.

این مخزن، کد بک‌اند دوراتو با زبان **Go** و ساختار پوشه‌های مبتنی بر **Clean Architecture** را نگهداری می‌کند.

## وضعیت فعلی

پروژه در مرحلهٔ راه‌اندازی پایهٔ بک‌اند است. در حال حاضر این بخش‌ها آماده‌اند:

- خواندن تنظیمات از فایل محلی `.env` با Viper.
- اجرای PostgreSQL و Redis با Docker Compose و بررسی سلامت هر دو سرویس.
- بررسی اتصال واقعی به PostgreSQL و Redis هنگام شروع برنامه.
- اجرای HTTP server و یک مسیر ساده برای بررسی درخواست و اتصال دیتابیس.
- چهار دستور برای روشن و خاموش کردن سرویس‌ها و برنامه.

برنامهٔ Go روی میزبان اجرا می‌شود و PostgreSQL و Redis در کانتینر هستند. فایل `Dockerfile` فعلاً خالی است. پوشه‌های ماژول‌ها، migration و تست، اسکلت توسعهٔ مراحل بعدی‌اند.

## قابلیت‌های هدف محصول

بر اساس سند امکان‌سنجی دوراتو، قابلیت‌های زیر در محدودهٔ نسخهٔ اولیهٔ محصول قرار دارند و پیاده‌سازی آن‌ها در ادامهٔ توسعه انجام می‌شود:

| ماژول | شرح |
| --- | --- |
| عضویت و ورود | ورود به حساب با شمارهٔ موبایل و کد یک‌بارمصرف؛ ورود مهمان به اکیپ با لینک دعوت و رمز |
| مدیریت اکیپ و اعضا | ساخت اکیپ، مدیریت اعضا، نقش مالک و عضو، انتقال مالکیت و آرشیو |
| مدیریت دنگ | ثبت هزینه، تعیین سهم اعضا، ساده‌سازی بدهی‌ها و ثبت تسویه |
| چک‌لیست | ساخت فهرست مشترک و تقسیم وظایف بین اعضا |
| نظرسنجی | ثبت سؤال و گزینه‌ها، رأی‌گیری و مشاهدهٔ نتیجه |
| قرعه‌کشی | انتخاب تصادفی از بین اعضا یا گزینه‌های دلخواه |
| گالری | بارگذاری و مدیریت تصاویر مشترک اکیپ |
| آرشیو خاطرات | دسترسی به خاطرات و تصاویر اکیپ‌های پایان‌یافته |
| مدیریت دوستان | ارسال و پاسخ به درخواست دوستی و مدیریت ارتباطات |
| اعلان‌های تلگرام | ارسال اعلان‌های مالی و رویدادهای مرتبط با اکیپ |
| تبلیغات | نمایش تبلیغات در اکیپ عادی و حذف آن در اکیپ پرمیوم |

خرید و مصرف توکن برای پرمیوم کردن اکیپ در محدودهٔ مدیریت اکیپ و دنگ تعریف شده است. سند محصول، پنل مدیریت سامانه را نیز برای گزارش‌گیری و رسیدگی به گزارش‌های کاربران پیش‌بینی می‌کند.

همیار هوشمند، نشان‌ها و امتیازها، پلی‌لیست مشترک و مینی‌گیم، قابلیت‌های تکمیلی برای مراحل بعدی هستند.

## فناوری‌های فعلی

| بخش | ابزار |
| --- | --- |
| زبان | Go `1.25.8` |
| سرور HTTP | کتابخانهٔ استاندارد `net/http` |
| پایگاه داده | PostgreSQL با ایمیج `postgres:15-alpine` |
| اتصال PostgreSQL | `pgx/v5` و connection pool |
| Redis | ایمیج `redis:7-alpine` و کلاینت `go-redis/v9` |
| تنظیمات | Viper |
| اجرای سرویس‌ها | Docker Compose |
| دستورهای توسعه | GNU Make |

نسخهٔ Go و وابستگی‌های برنامه در [go.mod](go.mod) مشخص شده‌اند.

## پیش‌نیازها

محیط اجرای دستورهای این راهنما **Linux یا Windows با WSL 2** است.

- Go با نسخهٔ مشخص‌شده در `go.mod`.
- Docker فعال و Docker Compose نسخهٔ ۲ با پشتیبانی از `up --wait`.
- GNU Make؛ در Ubuntu با دستور `sudo apt install make` نصب می‌شود.
- Git برای دریافت مخزن.
- دسترسی اینترنت برای دریافت ایمیج‌ها و وابستگی‌های Go در اولین اجرا.

در ویندوز، Go و Make باید داخل توزیع WSL مورد استفاده در دسترس باشند. برای Docker می‌توان از موتور نصب‌شده داخل WSL یا Docker Desktop با اتصال فعال به همان توزیع استفاده کرد.

قبل از شروع، در ترمینال Linux یا WSL بررسی کنید:

<div dir="ltr">

```sh
go version
docker compose version
docker info
make --version
```

</div>

## راه‌اندازی محلی

### ۱. دریافت پروژه

<div dir="ltr">

```sh
git clone https://github.com/Doratou/Backend.git
cd Backend
git switch develop
```

</div>

اگر پروژه را قبلاً دریافت کرده‌اید، ترمینال را در ریشهٔ همان مخزن باز کنید؛ جایی که `Makefile` و `docker-compose.yml` قرار دارند.

### ۲. تنظیم متغیرهای محیطی

اگر فایل `.env` ندارید، از روی فایل نمونه بسازید. دستور زیر فایل موجود را بازنویسی نمی‌کند:

<div dir="ltr">

```sh
test -f .env || cp .env.example .env
```

</div>

سپس تمام کلیدهای `.env` را مقداردهی کنید. جدول زیر یک تنظیم مناسب برای توسعهٔ محلی است:

| کلید | مقدار نمونه | کاربرد |
| --- | --- | --- |
| `HTTP_DOMAIN` | `0.0.0.0` | آدرس گوش‌دادن سرور HTTP |
| `HTTP_PORT` | `8080` | پورت برنامه |
| `PDB_HOST` | `127.0.0.1` | آدرس اتصال برنامه به PostgreSQL |
| `PDB_PORT` | `15432` | پورت PostgreSQL روی میزبان |
| `PDB_USER` | `admin` | نام کاربر دیتابیس |
| `PDB_PASSWORD` | رمز محلی دلخواه | رمز کاربر دیتابیس |
| `PDB_DB_NAME` | `doratou` | نام دیتابیس |
| `PDB_SSL_MODE` | `disable` | تنظیم SSL برای اتصال محلی |
| `RDB_HOST` | `127.0.0.1` | آدرس اتصال برنامه به Redis |
| `RDB_PORT` | `16379` | پورت Redis روی میزبان |
| `RDB_PASSWORD` | رمز محلی دلخواه | رمز اتصال Redis |
| `RDB_DB_NUMBER` | `0` | شمارهٔ دیتابیس Redis |

برای دو کلید رمز، مقدار واقعی دلخواه خود را بنویسید. اگر رمز شامل `$` یا `#` است، مقدار را داخل کوتیشن تکی قرار دهید.

Compose و برنامه، تنظیمات را از همان `.env` می‌خوانند. چون برنامه روی میزبان اجرا می‌شود، آدرس دیتابیس و Redis در این تنظیم محلی `127.0.0.1` است. در صورت اشغال بودن پورت‌ها، مقدار کلید مربوط را در `.env` تغییر دهید.

فایل `.env` در `.gitignore` قرار دارد. فایل [`.env.example`](.env.example) فقط کلیدها را با مقادیر خالی نگهداری می‌کند تا هر عضو تیم تنظیمات محلی خودش را وارد کند.

### ۳. روشن کردن PostgreSQL و Redis

<div dir="ltr">

```sh
make up
docker compose ps
```

</div>

دستور `make up` هر دو سرویس را روشن می‌کند و تا موفق شدن بررسی سلامت آن‌ها منتظر می‌ماند. در خروجی `docker compose ps` باید وضعیت سرویس‌های `db` و `redis` برابر `healthy` باشد.

### ۴. اجرای برنامه

<div dir="ltr">

```sh
make run
```

</div>

برنامه ابتدا build می‌شود و سپس در همان ترمینال اجرا می‌شود. با مقادیر نمونهٔ بالا، این پیام‌ها نشان‌دهندهٔ راه‌اندازی موفق‌اند:

<div dir="ltr">

```text
PostgreSQL connected
Redis connected
HTTP server listening on 0.0.0.0:8080
```

</div>

اگر اتصال یکی از سرویس‌ها ناموفق باشد، برنامه با خطا متوقف می‌شود و سرور HTTP شروع به کار نمی‌کند.

## دستورهای روزمره

| دستور | عملکرد |
| --- | --- |
| `make up` | روشن کردن PostgreSQL و Redis و انتظار برای آماده شدن آن‌ها |
| `make down` | توقف و حذف کانتینرهای پروژه با حفظ volumeهای داده |
| `make run` | build و اجرای برنامه در ترمینال فعلی |
| `make stop` | ارسال سیگنال توقف به برنامهٔ اجراشده با `make run` |

برای توقف کامل، یک ترمینال دوم در **همان پوشهٔ پروژه** باز کنید:

<div dir="ltr">

```sh
make stop
make down
```

</div>

برنامه با `Ctrl+C` هم متوقف می‌شود. فایل اجرایی و شناسهٔ پردازش در یک مسیر موقت مخصوص همان کاربر و مسیر پروژه، زیر `/tmp` نگهداری می‌شوند.

PostgreSQL و Redis volumeهای جداگانه دارند. اجرای `make down` داده‌های ذخیره‌شدهٔ آن‌ها را حذف نمی‌کند.

### استفاده از PowerShell در ویندوز

می‌توانید از داخل پوشهٔ پروژه در PowerShell، دستورها را به WSL بفرستید:

<div dir="ltr">

```powershell
wsl --exec make up
wsl --exec make run
```

</div>

برای توقف، در PowerShell دوم و از همان پوشه:

<div dir="ltr">

```powershell
wsl --exec make stop
wsl --exec make down
```

</div>

اجرای واقعی این دستورها داخل توزیع پیش‌فرض WSL انجام می‌شود؛ ابزارهای موردنیاز باید در همان توزیع آماده باشند. `Makefile` فعلی از ابزارهای پردازش Linux استفاده می‌کند و اجرای مستقیم آن با Make ویندوز پشتیبانی نمی‌شود.

## بررسی اجرای درست

با تنظیمات نمونه، در مرورگر آدرس [http://localhost:8080/](http://localhost:8080/) را باز کنید یا در ترمینال Linux یا WSL درخواست زیر را بفرستید:

<div dir="ltr">

```sh
curl -i http://localhost:8080/
```

</div>

| درخواست | وضعیت موفق | بدنهٔ پاسخ |
| --- | --- | --- |
| `GET /` | `200 OK` | `Salam` |

در این مسیر، هر درخواست یک `SELECT 1` روی PostgreSQL اجرا می‌کند. اگر دیتابیس در دسترس نباشد، پاسخ `503 Service Unavailable` برمی‌گردد. اتصال Redis فقط در شروع برنامه با `PING` بررسی می‌شود.

اگر `HTTP_PORT` را تغییر داده‌اید، پورت جدید را در آدرس درخواست هم وارد کنید.

| --- | --- |
| دستور `make` پیدا نمی‌شود | Make را داخل Linux یا توزیع WSL مورد استفاده نصب کنید. |
| Docker در دسترس نیست | خروجی `docker info` و فعال بودن موتور Docker یا اتصال Docker Desktop به WSL را بررسی کنید. |
| خطای متغیر خالی در Compose | فایل `.env` را در ریشهٔ پروژه بسازید و کلید اعلام‌شده در خطا را مقداردهی کنید. |

| خطای `RDB_DB_NUMBER` | برای این کلید یک عدد صحیح نامنفی وارد کنید؛ مقدار محلی معمول `0` است. |
| پیام `Application is already running` | برنامهٔ قبلی را با `make stop` از همان مسیر پروژه متوقف کنید. |

## قالب ایمیل کد تأیید

قالب HTML و متن ساده در `internal/infrastructure/email/templates/otp` نگهداری می‌شوند و همراه تصویر سربرگ و فونت‌ها داخل فایل اجرایی قرار می‌گیرند. تصویر سربرگ به‌صورت inline همراه ایمیل ارسال می‌شود.

کلید اختیاری `EMAIL_FONT_BASE_URL` آدرس عمومی HTTPS پوشهٔ فونت‌هاست. اگر خالی باشد، ایمیل با فونت جایگزین Tahoma و Arial نمایش داده می‌شود. بک‌اند فایل‌های `regular.woff2` و `bold.woff2` را بدون نیاز به ورود از مسیر `/assets/email/fonts/` ارائه می‌کند.

برای فعال‌کردن ایران‌یکان، پس از در دسترس قرار گرفتن دامنهٔ عمومی HTTPS، مقدار این کلید را به آدرسی مانند `https://api.example.com/assets/email/fonts` تغییر دهید و برنامه را دوباره اجرا کنید. فونت سفارشی فقط در برنامه‌های ایمیلی که از آن پشتیبانی می‌کنند نمایش داده می‌شود؛ فونت جایگزین همچنان فعال است. آدرس localhost برای گیرندهٔ ایمیل قابل استفاده نیست.

## قرعه‌کشی گروهی

قرعه‌کشی با عنوان و ۲ تا ۱۰۰ گزینهٔ متنی ساخته می‌شود. هر گزینه یک وزن صحیح مثبت از ۱ تا ۱۰۰۰۰۰۰ دارد؛ مجموع وزن‌ها لازم نیست ۱۰۰ باشد. گزینه‌ها به کاربران یا اعضای گروه ارتباطی ندارند و همراه وزن‌ها در JSON ذخیره می‌شوند.

قرعه‌کشی ابتدا `DRAFT` است. سازنده می‌تواند عنوان و گزینه‌ها را قبل از اجرا ویرایش کند. اجرای قرعه‌کشی یک برنده را بر اساس وزن‌ها انتخاب می‌کند و نتیجه را با وضعیت `COMPLETED` ذخیره می‌کند. ارسال مجدد درخواست اجرا همان نتیجه و زمان قبلی را برمی‌گرداند. قرعه‌کشی انجام‌شده قابل ویرایش نیست و این فیچر اندپوینت حذف ندارد.

هر پنج مسیر زیر به توکن دسترسی، حساب فعال و عضویت فعال در همان گروه نیاز دارند. فقط سازنده می‌تواند ویرایش و اجرا کند. گروه غیرفعال فقط اجازهٔ مشاهده می‌دهد.

| متد | مسیر | کاربرد |
| --- | --- | --- |
| `POST` | `/api/v1/groups/{groupID}/draws` | ساخت پیش‌نویس |
| `GET` | `/api/v1/groups/{groupID}/draws` | لیست با صفحه‌بندی و فیلتر `DRAFT` یا `COMPLETED` |
| `GET` | `/api/v1/groups/{groupID}/draws/{drawID}` | جزئیات و نتیجه |
| `PATCH` | `/api/v1/groups/{groupID}/draws/{drawID}` | ویرایش پیش‌نویس توسط سازنده |
| `POST` | `/api/v1/groups/{groupID}/draws/{drawID}/run` | اجرای یک‌باره توسط سازنده |

قبل از استفاده، مایگریشن جدید را با `go run ./cmd/migrate up` اجرا کنید. نمونهٔ درخواست‌ها، پاسخ‌ها و خطاها در پوشهٔ `bruno/Lucky Draws` قرار دارد. در Environment برونو، `drawGroupId` و `drawId` را دستی تنظیم کنید؛ ورود از بخش Auth متغیر `token` را پر می‌کند.

## لیست نظرسنجی‌های گروه

پاسخ `GET /api/v1/groups/{groupID}/polls` در هر آیتم، علاوه بر مشخصات نظرسنجی، `options` با شناسه، عنوان و `vote_count` هر گزینه، `total_votes` و `my_option_id` کاربر فعلی را برمی‌گرداند. ساختار هر آیتم با پاسخ جزئیات نظرسنجی یکسان است و برای نمایش کارت‌ها به درخواست جداگانه برای هر نظرسنجی نیاز نیست. درصد هر گزینه در فرانت محاسبه می‌شود؛ اگر مجموع رأی‌ها صفر باشد، درصد همهٔ گزینه‌ها صفر است.

صفحه‌بندی و فیلتر `status=ACTIVE` یا `status=INACTIVE` حفظ شده‌اند. `is_frozen` وضعیت گروه را نشان می‌دهد و `closed_at` زمان واقعی بسته‌شدن نظرسنجی یا `null` است. نظرسنجی خصوصی فقط مجموع رأی‌ها و انتخاب خود کاربر را نشان می‌دهد؛ هویت رأی‌دهندگان فقط از مسیر مخصوص نظرسنجی عمومی قابل دریافت است.

## داده‌های نمونهٔ نظرسنجی و قرعه‌کشی

پس از اجرای مایگریشن‌ها، با روشن‌شدن برنامه سید این دو بخش هم خودکار اجرا می‌شود. در گروه با شناسهٔ `1` سه نظرسنجی نمونه (عمومی فعال، خصوصی فعال و بسته‌شده) با گزینه‌ها و رأی‌ها، و سه قرعه‌کشی نمونه (دو پیش‌نویس با سازنده‌های متفاوت و یک انجام‌شده) قرار می‌گیرد. عنوان نمونه‌ها با `[نمونه]` شروع می‌شود.

در اولین گروه غیرفعال موجود نیز یک نظرسنجی و یک قرعه‌کشی برای بررسی حالت فریز ساخته می‌شود. سازنده و رأی‌دهندگان از اعضای فعال با حساب فعال انتخاب می‌شوند؛ اگر فقط یک عضو فعال وجود داشته باشد، نمونه‌ها همان سازنده را دارند. شناسهٔ نمونه‌ها را از پاسخ لیست دریافت کنید و در محیط Bruno یا Postman دستی بگذارید.

سید نظرسنجی و قرعه‌کشی فقط نمونه‌های ساخته‌نشده را اضافه می‌کند. اجرای مجدد، سؤال، گزینه‌ها، وزن‌ها، رأی‌ها، وضعیت، نتیجه و زمان اجرای نمونه‌های موجود را بازنویسی نمی‌کند و نظرسنجی حذف‌شده به‌صورت نرم یا رأی پس‌گرفته‌شده را برنمی‌گرداند. این رفتار مربوط به سید این دو بخش است؛ سید قبلی کاربران و گروه‌ها همچنان رفتار خودش را دارد.

## کد دوستی و پیدا کردن کاربر

هر حساب یک `friend_code` یکتا و ثابت مانند `DR-7K9M2X8Q4P6R` دارد. بخش بعد از `DR-` شامل ۱۲ حرف و رقم تصادفی است و حروف `I` و `O` و ارقام `0` و `1` استفاده نمی‌شوند. این کد برای اشتراک‌گذاری عمومی است و توکن ورود یا تأیید خودکار دوستی نیست.

قبل از اجرای این نسخه، `go run ./cmd/migrate up` را اجرا کنید. مایگریشن `20261111183000_add_user_friend_codes.sql` برای کاربران فعلی، حتی حساب‌های حذف‌شدهٔ نرم، کد می‌سازد. PostgreSQL برای حساب‌های جدید و کاربران سید هم به‌طور خودکار کد تولید می‌کند؛ سرویس به افزونهٔ جدید دیتابیس نیاز ندارد. کدها در کل جدول یکتا هستند و اجرای دوبارهٔ برنامه، ورود، تغییر رمز و آواتار یا بازیابی حساب، آن‌ها را تغییر نمی‌دهد. کد حساب غیرفعال یا حذف‌شده به کاربر دیگری داده نمی‌شود.

| متد | مسیر | کاربرد |
| --- | --- | --- |
| `GET` | `/api/v1/users/me` | اطلاعات حساب خود کاربر همراه `friend_code` |
| `GET` | `/api/v1/users/by-friend-code/{friendCode}` | پیدا کردن یک کاربر با کد کامل و نمایش مشخصات عمومی |
| `POST` | `/api/v1/friendships/requests` | ارسال درخواست با `receiver_user_id` پس از تأیید مشخصات |

دو مسیر جدید به توکن دسترسی و حساب فعال نیاز دارند. کد خود کاربر علاوه بر مسیر `users/me`، در پاسخ ثبت‌نام، ورود با رمز یا OTP و تغییر آواتار نیز برمی‌گردد. ورودی و ساختار قبلی این عملیات حفظ شده و فقط فیلد `friend_code` به اطلاعات کاربر اضافه شده است.

فلو فرانت: کاربر کد دوستش را وارد می‌کند، مشخصات عمومی را می‌بیند و پس از تأیید، `data.id` پاسخ را به‌عنوان `receiver_user_id` در اندپوینت ارسال درخواست می‌فرستد. جست‌وجو دقیق است و با نام، ایمیل یا بخشی از کد انجام نمی‌شود؛ حروف کوچک به بزرگ تبدیل و فاصلهٔ اطراف کد حذف می‌شود. پاسخ فقط `id`، `name`، `avatar_attachment_id` و `avatar_url` دارد. اگر آواتار قابل دسترسی نباشد، URL برابر `null` است و فرانت تصویر پیش‌فرض نشان می‌دهد.

کد با فرمت نامعتبر خطای `400 FRIEND_CODE_INVALID` می‌دهد. کد حساب غایب، غیرفعال یا حذف‌شدهٔ نرم با `404 USER_NOT_FOUND` پاسخ داده می‌شود. پیدا کردن کاربر هیچ درخواستی ثبت نمی‌کند؛ ارسال درخواست، وضعیت حساب و تمام قوانین قبلی فرندشیپ از جمله درخواست به خود، درخواست تکراری، دوستی موجود و مهلت ارسال مجدد را دوباره بررسی می‌کند.

در Bruno، درخواست `Get My Profile` در پوشهٔ `Users` و درخواست `Find User By Friend Code` در پوشهٔ `Friendships` قرار دارد. کد دوست را در متغیر معمولی `friendCode` وارد و ذخیره کنید، نتیجه را بررسی و شناسه را دستی در `receiver_user_id` بگذارید. این درخواست‌ها متغیرهای محیط را خودکار تغییر نمی‌دهند. نمونه‌ها و فهرست دقیق خطاها در مستندات هر درخواست هستند.
